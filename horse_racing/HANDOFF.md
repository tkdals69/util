## 0. 너(AI)에게 주는 역할과 절대 규칙

너는 경마 정량분석가다. 목표는 **실데이터로 정직한 walk-forward 백테스트를 돌리고**, 적중률과 수익률(ROI)을
개선하는 것이다. 다음 규칙은 어떤 경우에도 어기지 마라.

1. **미래 데이터 금지.** 테스트일 D의 예측에는 D 이전 데이터만 쓴다. 같은 날 앞 경주 결과도 쓰지 않는다.
   매 실행마다 `features.check_no_leakage()` 가 0을 반환해야 한다. 새 피처를 추가하면 이 검사에 포함시켜라.
2. **테스트 기간으로 튜닝 금지.** 임계값·하이퍼파라미터·피처 선택은 학습기간 안의 홀드아웃으로만 정한다.
   최종 테스트(최근 4주)는 **딱 한 번**만 본다. 여러 번 보고 고르면 그 결과는 무효다.
   개발용으로는 그보다 이전 기간(예: 8~4주 전, 6개월 전 등)을 별도 검증 구간으로 써라.
3. **가짜 데이터 결과를 성과로 보고 금지.** `--synthetic` 은 코드 동작 확인용이다.
4. **데이터가 없으면 지어내지 마라.** 출마표·배당·결과를 못 가져오면 못 가져왔다고 보고하라.
5. 결과 보고 시 항상 **ROI, 부트스트랩 95% CI, 베팅 수, 경주 적중률, 최대낙폭**을 같이 적어라.
   적중률만 높고 ROI가 음수면 "실패"로 분류하라.

## 1. 현재 상태 (이미 구현됨)

| 파일 | 내용 |
|---|---|
| `data.py` | data.go.kr KRA OpenAPI 수집(캐시), 필드 정규화(`rcDate, meet, rcNo, chulNo, hrNo, ord, winOdds, plcOdds, wgHr ...`), CSV 로더 |
| `features.py` | 시점 기준 피처 ~70개, `check_no_leakage()` |
| `model.py` | 1단계 LightGBM(배당 미사용) → 경주 내 softmax, 2단계 조건부 로짓으로 시장확률 결합(Benter 1994), Harville 연승확률 |
| `betting.py` | S0 인기마 단승 / S1 모델1위 / S2 밸류단승 / S3 밸류연승 / S4 1/4 켈리 / S5 인기마 연승 / S6 고적중 연승 / S7 고적중 더칭 |
| `backtest.py` | 주간 walk-forward(매주 재학습), 로그손실(시장 vs 모델), 캘리브레이션, 결과 CSV |
| `synthetic.py` | 가짜 데이터 생성기(동작 확인용) |

가짜 데이터 확인 결과(의미 없음, 참고용): 적중률 70~84% 전략(S5~S7)은 전부 ROI -10~-25%.
적중률을 올리면 배당이 낮아져 수익이 안 난다는 구조를 확인했을 뿐이다.

**아직 못 한 것: 실데이터로 한 번도 안 돌렸다.** (이전 환경은 kra.co.kr / data.go.kr 접속 차단)

## 2. 1단계 — 실데이터 확보 (최우선)

1. data.go.kr 회원가입 → "한국마사회 경주기록정보"(또는 "경주성적정보", "출전표 상세정보") 활용신청 → 서비스키 발급.
2. 실제 응답 필드명을 먼저 확인하라:
   ```bash
   curl "https://apis.data.go.kr/B551015/API214_1/RaceDetailResult_1?serviceKey=$KRA_API_KEY&pageNo=1&numOfRows=5&meet=1&rc_date=20261115&_type=json"
   ```
   필드명이 다르면 `data.py`의 `COLUMN_ALIASES` 에 추가. 엔드포인트가 다르면 `KRA_ENDPOINT` 수정.
   **확정 단승배당(winOdds)과 연승배당(plcOdds)이 반드시 있어야 한다.** 없으면 배당 API를 따로 찾아 조인.
3. 최소 2년치(서울 meet=1, 제주 2, 부경 3) 수집: `KRA_API_KEY=... python backtest.py --fetch --today YYYY-MM-DD --weeks 4`
4. 데이터 품질 리포트를 먼저 내라: 경주 수, 경주당 두수 분포, 배당 결측률, 1번인기 승률(정상: 약 30~35%),
   단승 환급률 = Σ(1착 배당)/경주수 (정상: 약 0.75~0.80). 이 값이 크게 벗어나면 파싱 오류다.

```bash
python backtest.py --csv data.csv --today 2026-11-20 --weeks 4
python backtest.py --csv data.csv --today 2026-11-20 --weeks 26   # 6개월: 표본 늘리기
```

보고할 것:
- 주차별 로그손실: 시장 vs 펀더멘털 vs 결합. **결합 < 시장** 이어야 모델에 정보가 있는 것.
- θ_fund / θ_mkt (θ_fund ≈ 0 이면 모델이 시장보다 아는 게 없음)
- 전략별 ROI·CI·적중률·낙폭, 캘리브레이션 표
- 경마장(서울/부경/제주)별, 거리별, 등급별, 두수별 ROI 분해

## 4. 3단계 — 개선 아이디어 (우선순위 순)

각 아이디어는 **검증 구간에서만** 효과를 측정하고, 로그손실이 시장 대비 개선되는지 + ROI 변화를 표로 남겨라.

### A. 데이터/피처 (효과 큰 순)
1. **스피드 지수**: 경주기록을 (경마장, 거리, 주로상태, 날짜)로 보정한 표준화 기록. 주로 상태별 기준기록은
   과거 데이터로만 계산(expanding). 일본·미국식 Beyer/Timeform 방식 참고.
2. **구간 기록(S1F, G1F, 3F)**: 선행마/추입마 성향 분류 → 경주 내 선행마 수(페이스 예측)와 각 말 성향의 궁합.
3. **조교(훈련) 기록**: KRA "조교현황" API. 최근 조교 횟수·강도.
4. **혈통**: 부마별 거리·주로(습/건) 적성 승률(베이지안 수축).
5. **게이트 편향**: 경마장×거리별 게이트 위치 승률(과거 데이터로만).
6. **장구/체중/휴양**: 마체중 급변, 장구 변경(차안대 등), 휴양 후 복귀 경주 수.
7. **기수 교체**: 상위 기수로 교체 여부, 기수-말 조합 이력.
8. **등급 이동**: 승급/강급 직후 성적.
9. **시장 피처(2단계 전용)**: 배당 변동(조기 배당 → 확정 배당의 움직임). 데이터가 있으면 매우 강력.
   단, 실전에서 쓸 수 있는 시점의 배당만 써야 한다.

### B. 모델
1. LightGBM `lambdarank`(경주 단위 랭킹) vs 현재 binary 비교.
2. 착순 전체를 쓰는 **Plackett-Luce** 손실 → 1착뿐 아니라 2·3착 정보 활용(연승·복승에 유리).
3. 경마장별 분리 모델 vs 통합 모델 + 경마장 피처.
4. Harville 대신 **Henery/Stern 보정** 연승확률(Harville은 2·3착 확률에서 인기마를 과대평가하는 경향).
5. 2단계 결합식에 두수, 경마장별 θ, 배당 구간별 favorite-longshot bias 보정 항 추가.
6. 여러 seed / 여러 학습창(1년, 2년) 앙상블.
7. Optuna로 하이퍼파라미터 탐색 — **반드시 내부 시계열 CV(학습기간 내)** 로만.

### C. 베팅 전략 (적중률 vs 수익률)
1. **복승/쌍승/삼복승**: 모델 확률로 조합 확률 계산(Harville/Stern) → EV>1 조합만. 단승보다 시장 비효율이 큼.
2. **고적중 목표 전략 재설계**: "적중률 ≥ 70% AND ROI ≥ 0" 을 동시에 만족하는 구간이 있는지 탐색.
   (예: 모델 연승확률 0.8 이상인데 연승배당 1.4 이상인 경우만). 없으면 "없다"고 보고.
3. 밸류 임계값(edge), 최소 확률, 최대 배당을 홀드아웃에서 그리드서치 → 테스트엔 고정값 적용.
4. 켈리 비율(1/8, 1/4, 1/2) 비교, 경주당 상한.
5. **배당 영향 모델링**: 내 베팅이 풀(pool)에 들어가면 배당이 떨어진다. 풀 크기 대비 베팅액으로 배당 하향 보정.
6. 확정배당 대신 **마감 N분 전 배당**으로 정산하는 시나리오(데이터 있으면). 없으면 확정배당 × 0.95 등 보수적 가정도 같이 보고.

### D. 평가 강화
1. 테스트 기간 4주 → 26주/52주로 늘려 CI 좁히기.
2. 다른 시작일 여러 개로 반복(rolling origin) → 결과의 분산 보고.
3. 다중비교 보정: 전략 N개를 시도했으면 최고 ROI는 과대평가됨. 화이트 리얼리티 체크 또는 단순히
   "개발 구간 1등 전략을 최종 테스트에 한 번만" 적용.
4. 무작위 베팅 기준선(같은 배당대 말을 무작위로) 대비 개선폭.

## 5. 4단계 — 당일 추천 도구 (선택)

`recommend.py` 를 만들어라:
- 입력: 당일 출마표(KRA 출전표 API 또는 CSV) + 현재 배당(수동 입력 가능)
- 처리: 전날까지 데이터로 학습된 모델 로드 → 각 말 승률/연승확률 → EV 계산
- 출력(경주별): 발주시각, 말별 승률·연승확률·배당·EV, 추천(단승/연승/복승/패스), 권장 금액(예산 대비 %), 근거 3줄
- 패스가 많은 것이 정상이다. 모든 경주를 추천하지 마라.

## 6. 산출물

1. `REPORT.md`: 데이터 품질 → 기준선 → 개선별 효과표(검증구간) → 최종 테스트 1회 결과 → 결론
2. `results/` CSV 일체, 사용한 명령어 전부
3. 결론에는 다음 질문에 숫자로 답하라:
   - 모델이 시장보다 정보가 있는가? (로그손실 차이, θ_fund, CI)
   - 적중률 70%+ 이면서 ROI ≥ 0 인 전략이 존재하는가?
   - ROI 95% CI 하한이 0 이상인 전략이 있는가? 없으면 "실전 투입 근거 없음"으로 결론.

## 7. 참고
- 단승·연승 환급률 약 80% → 무작위 베팅 기대 ROI ≈ -20%. 이것이 넘어야 할 기준선.
- 연승: 7두 이하 2착까지, 8두 이상 3착까지.
- Benter, W. (1994) "Computer Based Horse Race Handicapping and Wagering Systems: A Report".
- Bolton & Chapman (1986) 다항 로짓 경마 모델, Stern (1990) 순위 확률 모델.
